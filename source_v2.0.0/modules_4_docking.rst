Docking
*************

hdock
--------------

This module allows the use of HDOCK (see the hdock-builder Docker image at https://hub.docker.com/r/pegi3s/hdock-builder), a hybrid docking protocol that combines both template-based and template-free approaches. 
It takes two .pdb files as input and returns the .pdb files of the 100 highest scoring docking protein complexes generated by HDOCK. 
The ligand and receptor .pdb files should follow the ``<protein_id>.pdb`` naming structure. The module expects the .pdb files of the corresponding proteins to be placed in the ``PDBs/Ligands`` and ``PDBs/Receptor`` folders. 
If more than one ligand .pdb file is present in the ``PDBs/Ligands`` folder, the module will proceed with the analysis of the corresponding receptor-ligand combinations.

If running this command alone, ``copy`` commands must first be invoked to copy the ligand and receptor PDB files to ``PDBs/Ligands`` and ``PDBs/Receptor``, respectively. This module can be used as part of a block and requires the ligand list.


haddock
--------

This module allows the use of HADDOCK (see the haddock24-builder Docker image at https://hub.docker.com/r/pegi3s/haddock24-builder), an information-driven flexible docking approach that accurately models the 3D structure of macromolecular complexes. 
It returns the PDBs of the docking protein complexes with a z-score less than or equal to 0. The complex clusters resulting from all possible predicted dockings are scored based on a statistic called the z-score. 
The z-score represents how many standard deviations the HADDOCK score of a given cluster is from the mean of all clusters obtained. The lower the z-score, the better the predictions. 
If the user wants to see all the files created during the docking process, the parameter ``haddock_all_files`` can be set to ``y``. If the user only wants to keep the most important files, this parameter can be set to ``n``.

The ligand and receptor PDB files should follow the ``<protein_id>.pdb`` naming structure. The module also uses the active and passive sites of each protein, which must follow the naming structure ``<protein_id>_active.sites`` and ``<protein_id>_passive.sites``. 
The active and passive site files must be placed inside a folder named ``<protein_id>`` within the module's input folder. The module expects the .pdb files of the corresponding proteins to be placed in the ``PDBs/Ligands`` and ``PDBs/Receptor`` folders.

If running this command alone, ``copy`` commands must first be invoked to copy the ligand and receptor PDB files to ``PDBs/Ligands`` and ``PDBs/Receptor``, respectively. This module can be used as part of a block and does not require the ligand list.


pydock_ftdock
--------------

This module facilitates the use of the FTDock software as implemented in the pyDock software (see the pydock3-builder Docker image at https://hub.docker.com/r/pegi3s/pydock3-builder). It returns the PDBs of the docking protein complexes with the highest score. 
The parameter ``pydock_ftdock_number_of_solutions`` specifies the number of solutions to analyze. This number must be less than or equal to 10000 (recommended: 100). 
The parameter ``pydock_ftdock_best_pdb`` specifies the number of best solutions to retain (recommended: 5).

The ligand and receptor .pdb files should follow the ``<protein_id>.pdb`` naming structure. FTDock also uses the active and passive sites of each protein, which must follow the naming structure ``<protein_id>_active.sites`` and ``<protein_id>_passive.sites``. 
The active and passive site files must be placed inside a folder named ``<protein_id>`` within the module's input folder. The module expects the .pdb files of the corresponding proteins to be placed in the ``PDBs/Ligands`` and ``PDBs/Receptor`` folders.

If running this command alone, ``copy`` commands must first be invoked to copy the ligand and receptor PDB files to ``PDBs/Ligands`` and ``PDBs/Receptor``, respectively. This module can be used as part of a block and does not require the ligand list.
