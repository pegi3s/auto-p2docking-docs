Data analysis and visualization
***************

distance_tree
-----------

This module can be used to load a file named ``tabulated.tsv`` (as generated by the ``tabulate`` module), to produce a distance matrix, an UPGMA tree based on the distance matrix, and a file with the input data ordered as shown on the UPGMA tree. One parameter must be declared in the config file, namely ``vt_columns``, which determines the size of the SVG image that is produced (we suggest 5000). There is also an additional parameter that can be declared, namely ``distance_tree_coordinates``, which can be used to consider only some positions of the protein being analyzed. For instance, ``distance_tree_coordinates="1-100,400-500"`` means that only the regions comprised between amino acid positions 1-100 and 400-500 will be considered.


get_pattern
-----------

This module takes as input the table created by the ``tabulate`` module and returns a file named ``pattern_positions.txt`` containing the pattern positions for structure 1 according to the rule and cutoff value specified in the auto-p2docking configuration file, which may look like this::

   pattern_cutoff=50
   pattern="111[01]1"

The ``pattern_cutoff`` parameter is the value, in percentage, above which a site is assigned as "1" in the rule pattern. The ``pattern`` parameter is a regular expression defining the pattern rule. In the example above, ``111[01]1`` means that a pattern region is defined as a sequence of at least three consecutive sites with more than 50% frequency, followed by a site that may have more or less than 50% frequency, if followed by another site with more than 50% frequency.


highlight_regions
-----------

This module applies colors to PDB structures to highlight regions of interest based on the ``pattern_positions.txt`` file created by the ``get_pattern`` module, which must be present in the module's input folder. PDB structures generated by ``pisa_server_extract`` or ``pisa_ccp4_extract`` and stored in ``files_to_keep`` are automatically retrieved when available. Chain A (receptor) and chain B (ligand) are colored green and blue respectively, while the amino acid sites corresponding to the identified pattern are colored red. This module also uses PyMOL (https://pymol.org/) to generate PNG images of the colored structures.

This module cannot be used as part of a block and requires the ligand list.


tabulate
-----------

This module takes as input .tsv files generated by the ``pisa_server_extract``, ``pisa_ccp4_extract`` or ``pisa_xml_extract`` modules and creates a file named ``tabulated.tsv`` containing a table with the receptor-ligand interaction sites for the different ligands. The input files must be organized in subfolders named after the respective ligand within the module input folder.

This module cannot be used as part of a block and does not require the ligand list.


prodigy
-----------

This module uses PRODIGY to estimate the binding affinity of protein-protein complexes. It recursively processes .pdb files in the module input folder and requires each complex to contain at least two chains. The chains used in the calculation are defined by the ``prodigy_selection`` parameter in the main auto-p2docking config file, with ``A B`` used as the default selection. For each valid complex, the module generates a ``<complex_id>.prodigy.txt`` file containing the PRODIGY results, including the predicted binding affinity.

This module can be used as part of a block and does not require the ligand list.


prodigy_list
-----------

This module collects the individual results generated by the ``prodigy`` module and combines them into a file named ``prodigy_results.csv``. The module searches the input directory for the PRODIGY result files and generates the CSV file for subsequent analysis. The resulting ``prodigy_results.csv`` file is also copied to the ``files_to_keep`` folder.

This module cannot be used as part of a block and does not require the ligand list.


prodigy_stats
-----------

This module performs statistical analysis of the results generated by ``prodigy_list``. It takes a ``prodigy_results.csv`` file as input and generates statistical summaries, including ``prodigy_summary_stats.csv``. The generated results are also retained in ``files_to_keep/prodigy_stats_output``.

This module cannot be used as part of a block and does not require the ligand list.
